# 일본 여행 안전 가이드 (JapanTrip)

한국인 여행자를 위한 일본 여행 앱. **공항 이동 · 교통패스 · 관광지 · 실시간 지진 정보**를
하나로 묶는다. iOS · Android · Web 단일 코드베이스.

현재 버전은 **정보 제공에 집중한다.** 크레딧·기여 보상은 설계와 코드를 갖춰 두되
화면에서 감춰 뒀다 (`src/constants/features.ts`). 보상은 채울 정보가 충분해진 뒤에 열어야
어뷰징이 아니라 기여가 모이기 때문이다.

## 무엇이 다른가

| 기능 | 기존 방식의 문제 | 이 앱의 접근 |
|---|---|---|
| 공항 → 시내 | 노선이 너무 많아 초행자가 못 고른다 | 노선을 큐레이션하고 "추천 / 가장 빠름 / 가장 저렴"을 표시. 오프라인 동작 |
| 교통패스 | 가격만 나열하고 끝난다 | **언제 이득인지 · 뭐가 안 되는지 · 어디서 사는지 · 어떻게 쓰는지** 넷을 함께 적는다 |
| 관광지 | 좋다는 말만 하고 가는 법은 다른 앱을 켜게 만든다 | 가장 가까운 역·노선, 입장료, 권장 소요시간을 함께 담는다 |
| 맛집 평점 | 구글맵은 안 가본 사람도 별점을 남긴다 | GPS 현장 인증을 통과한 리뷰만 평점에 반영 |
| 지진 정보 | 앱을 따로 깔아야 하고 일본어다 | 기상청 발표를 한국어 + 진도별 행동 지침으로 변환 |

## 화면

탭 5개와 상세 화면들로 구성된다.

| 탭 | 내용 |
|---|---|
| 홈 | 안전 상태 요약 · 바로가기 · 지금 자세히 다루는 도시 |
| 공항 | 7개 공항 → 노선별 소요시간·요금 비교, 공항별 함정 |
| 이동 | 도시별 교통패스 6종, IC카드, 현지에서 헷갈리는 것들 |
| 관광 | 30여 곳 · 역/입장료/소요시간, 도시·분류 필터 |
| 안전 | 실시간 지진·긴급지진속보, 비상 연락처 |

상세: `airport/[id]` · `place/[id]` · `roadmap` · `rewards`(비활성)

## 디자인

원칙은 하나다 — **화면이 정보의 위계를 그대로 보여줄 것.** 여행 중 급하게 훑는
화면이라 꾸밈이 늘수록 판단이 느려진다.

- 그림자를 쓰지 않는다. 카드는 배경색 대비(`#F4F5F8`)로만 떠 있다
- 강조색은 인디고(`#4C5FD7`) 하나. 나머지 색은 상태(위험·주의·안전)에만 쓴다
- 여백이 곧 구획이다. 선 대신 간격으로 나눈다
- 모서리를 넉넉히 둥글린다(14~24). 정보 밀도가 높아도 부드럽게 읽히도록
- 카드 왼쪽의 4px 상태 띠가 이 앱의 시각적 표식이다

색 값은 이 앱의 고유 팔레트다. 특정 서비스의 브랜드 색을 그대로 가져다 쓰지 않는다 —
비슷해 보이는 것과 같은 값을 쓰는 것은 다른 문제이고, 후자는 분쟁의 빌미가 된다.

### 말투

설명은 전부 **옆에서 알려주듯** 쓴다. 여행 중에 급하게 읽는 글이라 격식보다 이해 속도가
중요하기 때문이다.

> "이 패스는 교통보다 입장료로 뽑는 거예요. 하루에 유료 관광지를 세 곳 이상 갈 생각이면
> 거의 무조건 이득이고, 지하철만 탈 거라면 오히려 손해예요."

안전 문구도 마찬가지지만, 여기서는 겁을 주지도 안심시키지도 않고 **해야 할 동작만**
앞에 둔다.

> "가구가 움직일 수 있어요. 머리를 감싸고 탁자 아래로 들어가세요. 엘리베이터는 타지 마세요."

코드 주석은 개발자용이라 문어체 그대로 둔다.

**폰트는 Pretendard** — SIL Open Font License 1.1로 배포되는 오픈소스 서체다. 상업 이용을
포함해 자유롭게 쓸 수 있다. 한글과 라틴 문자의 높이가 잘 맞고 숫자 폭이 일정해서 요금·
소요시간을 나열하는 이 앱과 잘 맞는다. Regular·SemiBold·Bold 3종을 번들에 포함했고
(약 7.7MB), 라이선스 전문은 `assets/fonts/Pretendard-LICENSE.txt` 에 함께 배포한다.
앱 안에서도 「정보 → 오픈소스 라이선스」에서 확인할 수 있다.

색·간격·타이포는 `src/constants/theme.ts` 한 곳에서 정의하고, 화면은 `src/components/ui.tsx`
의 컴포넌트만 조합한다. 화면 코드가 색을 직접 만지지 않아야 화면이 늘어나도 한 몸으로
유지된다.

## 데이터 소스

| 용도 | 소스 | 비용 | 상태 |
|---|---|---|---|
| 지진 · 긴급지진속보 | [P2P지진정보 JSON API v2](https://www.p2pquake.net/develop/json_api_v2/) | **무료 · 등록 불필요 · 상업 이용 가능** | 연동 완료 |
| 지진 (대체 경로) | [기상청 JMA](https://www.jma.go.jp/bosai/quake/data/list.json) | 무료 | 검증 완료, 미연동 |
| 공항 · 패스 · 장소 | 자체 큐레이션 | — | 공항 9 · 패스 18 · 장소 108 |

P2PQuake 레이트 리밋은 `/history` 기준 IP당 60회/분. 앱은 60초마다 폴링하고 백그라운드에서는
멈춘다.

### 요금 정보의 신뢰도

교통패스는 개정이 잦아 항목마다 `verified` 플래그를 둔다. 확인하지 못한 값은 금액 대신
「가격 변동 가능 · 판매처 확인」을 띄운다 — 틀린 숫자보다 없는 편이 낫다.

이번 작업에서 확인한 정정 사항:

- 교토 **버스 전용 1일권(700엔)은 폐지**됐다. 아직 그 가격을 안내하는 블로그가 많지만
  지금은 지하철·버스 1일권(1,100엔)이 유일한 대체다
- 오사카 주유패스 1일 3,500엔 / 2일 5,000엔
- 후쿠오카 투어리스트 시티패스 시내 2,500엔 / +다자이후 2,800엔
- 「간사이 스루패스」는 **간사이 레일웨이 패스**로 개명되며 조건이 개정됐다

## 제휴(어필리에이트) 설정

패스 구매 버튼에 추천 코드를 붙여 수수료를 받을 수 있다. 설정은
`src/constants/affiliates.ts` **한 곳만** 고치면 앱 전체에 반영된다.

```ts
klook: {
  referralId: '',   // ← 승인 후 발급받은 ID를 여기에
  ...
}
```

1. 파트너 프로그램에 가입하고 **승인**을 받는다 (승인 전에는 수수료가 잡히지 않는다)
   — [클룩](https://affiliate.klook.com) · [KKday](https://affiliate.kkday.com) · 마이리얼트립 파트너스
2. 발급받은 ID를 `referralId` 에 넣는다
3. 각 패스의 `buyLinks` 에 정확한 상품 URL(`productUrl`)을 넣는다.
   지금은 검색 URL이 기본값이라 링크는 열리지만 상품이 특정되지 않는다

동작 방식:

- `referralId` 가 비어 있으면 **추천 코드 없이** 원본 링크를 연다. 가짜 파라미터를 붙여
  링크를 깨뜨리지 않는다
- 이미 쿼리가 있는 상품 URL에도 안전하게 덧붙는다 (`?spm=abc` → `?spm=abc&aid=...`)
- URL 파싱에 실패해도 원본을 그대로 연다

### 🔴 대가성 표시는 법적 의무

공정거래위원회 「추천·보증 등에 관한 표시·광고 심사지침」상, 수수료를 받는 링크에는
경제적 이해관계를 **명확히** 표시해야 한다. 숨기거나 흐리게 적으면 표시광고법 위반이
될 수 있고 앱스토어 심사에서도 문제가 된다.

그래서 구매 버튼 바로 아래에 `DISCLOSURE` 문구가 항상 붙는다. 추천 ID가 설정된 경우에만
"수수료가 지급돼요" 문구로 바뀌고, 설정 전에는 단순 안내가 나간다. **이 문구를 지우거나
눈에 안 띄게 바꾸지 말 것.**

| 3 | 오키나와 · 나고야 · 시즈오카 | 대표 장소 또는 준비 중 |

## 인증 반경 — 왜 10m를 그대로 쓰지 않는가

기본 반경은 10m다. 다만 이 값을 거리와 그대로 비교하면 **진짜 방문자가 대량 탈락한다.**

- 스마트폰 GPS 오차는 개활지에서 약 5m지만, 도심 고층가에서는 20~50m, **실내에서는 그
  이상**으로 벌어진다. 리뷰를 쓰는 시점은 대개 가게 안이다
- 반대로 반경을 좁혀도 **위조는 못 막는다.** 모의 위치 앱은 좌표를 정확히 찍으므로
  반경이 10m든 300m든 똑같이 통과한다

그래서 두 가지를 둔다:

1. **기기 정확도를 반경에 더한다** — `거리 ≤ 반경 + accuracy`. 단 정확도가 65m를 넘으면
   판정을 거부한다(큰 오차를 핑계로 통과하는 것을 막는다)
2. **장소별 반경**(`Place.radiusM`) — 오도리공원 400m, 후시미이나리 300m, 츠키지 120m,
   작은 식당은 기본 10m. 좌표는 한 점이지만 시장·공원은 수백 m다

검증 케이스 9종(가게 안 · 실내 오차 · 길 건너 · 정확도 미달 · 시장 부지 안팎)이 모두
의도대로 동작한다.

## 검증 상태

- `tsc --noEmit` 통과
- 웹 번들 16개 라우트 생성, 모든 탭 화면에 본문 렌더 확인
- GPS 근접 판정 9/9 통과
- 제휴 링크 생성 5/5 통과 (미설정 · 설정 · 쿼리 있는 상품URL · 쿼리 없는 상품URL · 깨진 URL)

## 서버

현재 서버가 없다. 모든 상태가 기기 안에 있고 모든 판정이 클라이언트에서 일어난다.
정보 제공만 하는 지금 단계에서는 충분하지만, **크레딧을 켜기 전에는 반드시 원장을 서버로
옮겨야 한다.** 어디를 어떻게 옮겨야 하는지는 [docs/SERVER.md](docs/SERVER.md)에 정리했다.
